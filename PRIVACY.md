Partition Studio has no implemented telemetry, advertising, automatic update service, or intentional upload of disk inventories, file contents, SMART data, images or recovery reports.

The application reads information from disks selected by the operator. An exported inventory can contain model names, serial numbers, unique disk IDs, drive letters and labels. A full disk image or clone contains partition tables, allocated and unallocated areas, including private or deleted data. Images are not encrypted by this application. The operator chooses output locations and is responsible for access to those files. Review reports before publishing them.

Windows commands invoked by an explicitly requested operation remain subject to Windows configuration and policies. The current backup UI accepts local drive-letter destinations. Storage paths configured by the operator, including redirected paths, can still refer to external storage. Optional TestDisk/PhotoRec utilities run as separate upstream applications and are governed by their own behavior and documentation. This application does not inspect, intercept or upload their recovery results.

Build-time dependency downloads, cloud build logs, repository hosting and future signing requests are development activities, distinct from application telemetry. GitHub and a future signing provider process their own account/build metadata under their terms. The maintainer must review public artifacts to ensure they do not contain real disk inventories, secrets or personal data.

No contact details or diagnostic results from the original development machine are included in the publication draft. The public repository is https://github.com/frmaazevedo-spec/partition-studio; the connected GitHub maintainer proposed in the README is not presented here as a legal identity.
